# 가족해커톤 진행 기록

새 작업을 할 때마다 맨 아래에 날짜별로 추가한다. 학생·보호자 개인정보는 적지 않는다.

## 링크
- 저장소: https://github.com/joonssem/family-hackathon
- 배포(GitHub Pages): https://joonssem.github.io/family-hackathon/
- 무대 안내·타이머: `/stage.html`, 가족용 안내: `/guide.html`
- 교사 공유용 운영안 문서: Claude 문서 "가족해커톤 운영안 초안 및 논의 안건" (논의 후 이 폴더에 최종본 정리)

## 확정된 운영 조건
- 10가족(학생 1 + 보호자 1~2, 동생 포함 가족 등), 학생의 80% 이상이 1·2학년
- 장소: 학교 강당 (AP 2개, 무대 PC, 멀티비전, 마이크)
- 기기: 학교 공용 노트북 가족당 1대, Intune 관리, 게스트 로그인 (로그아웃하면 입력·저장 내용 삭제)
- 보호자 Google 계정으로 Gemini 사용. 비상 대책은 보호자 휴대전화 테더링
- 시간: 평소 1·2·3교시와 같음, 수업 40분, 쉬는 시간 10분
- 1차시: 가족 대화 + 스택 버거(실물 보드게임). 2차시: 가족 대화 중심으로 만들 것 정하기 + 프롬프트. 3차시: 제작·공유·발표
- 학생 이름 등 개인정보는 2차시 시작부터 입력하지 않도록 안내
- 가족별 진행 현황은 보류(저학년 부담)

## 결정됨
- 제출 방식: Padlet (2026-10-26). 가족이 Gemini 공유 링크를 Padlet 글로 붙여 넣는다. Supabase·교사 수합 갤러리는 쓰지 않는다.

## 방향 결정 (2026-10-27)
- 목적: 잘 만드는 것이 아니라, 가족이 함께 해결할 문제를 찾고 알맞게 해결하는 것
- 주제: 학생과 관련된 내용 또는 가족과 관련된 내용
- 발표: 되도록 모든 가족이 발표하기를 희망
- 운영 교사 3명, 웹페이지 제작은 한 명이 담당
- 강조점: 가족이 함께 한다는 것. 다만 학교 행사이므로 학생이 도전하는 것이 가장 의미 있다
- Padlet: 로그인 없이 안내한 링크로 글쓰기 허용. 이름 칸에는 가족 팀 이름을 쓰고, 학생·가족 개인정보가 없는 팀 이름을 정하도록 안내
- 경험: 같은 공용 노트북으로 AI 동아리를 2차시 진행했고, 이번 행사도 3차시 분량. 무대 PC는 강당 스피커와 연결되어 있고, 졸업식·입학식 행사 경험이 있음

## 아직 정해지지 않은 것

- 주제 선택지의 구체적 목록

- [ ] 공용 노트북에서 GitHub Pages와 CDN 폰트(jsdelivr)가 열리는지 (와이파이 접속은 확인됨, 노트북에서 폰트 표시까지 확인)
- [x] 강당 동시 접속: 아이패드 21대 동시 접속 확인 (2026-10-27)

- [ ] 타이머 동작·종료음을 무대 PC에서 직접 확인 (강당 스피커 연결됨, 행사 경험 있음. 타이머 종료음만 확인)

- [ ] Padlet 보드 만들기: 로그인 없이 글쓰기 허용, 외부 공개 차단(비공개 또는 링크 전용), 이름 입력 없이 올릴 수 있는지 확인, 주소를 `config.js`의 `padletUrl`에 입력
- [x] 공용 노트북(게스트)에서 Padlet 글쓰기가 되는지 (가능 확인, 2026-10-27)
- 나머지 노트북 점검(방치·절전, Google·Gemini 로그인, 폰트, 공유 링크)은 2026-10-28 테스트 예정
- [ ] Gemini 공유 링크를 만든 뒤 보호자 계정 밖의 노트북에서도 열리는지

## Intune·게스트 로그인 조사 (2026-10-26, 공개 문서 기준)
학교 테넌트의 실제 Intune 설정은 관리 센터(intune.microsoft.com) 로그인이 필요해 확인하지 못했다. 아래는 공개 문서에서 확인한 것이며, 학교 정책 확인은 정보 담당자에게 요청해야 한다.

- 게스트에는 두 종류가 있어 어느 쪽인지 확인이 필요하다.
  - Windows 게스트 로그인: Intune의 공유 기기 설정에서 로그인 화면에 Guest 옵션을 켤 수 있다. 계정을 로그아웃 후 또는 비활성 일수(0~60일) 기준으로 자동 삭제하도록 정할 수 있다. ([Windows shared device settings](https://learn.microsoft.com/en-us/intune/intune-service/configuration/shared-user-device-settings-windows), [Configure a shared or guest Windows device](https://learn.microsoft.com/en-us/windows/configuration/shared-pc/set-up-shared-or-guest-pc?tabs=intune))
  - Edge 게스트 프로필: `BrowserGuestModeEnabled` 정책으로 허용 여부를 정한다. 게스트 창을 모두 닫으면 탐색 데이터가 삭제된다. ([정책 문서](https://learn.microsoft.com/en-us/deployedge/microsoft-edge-policies/browserguestmodeenabled))
- 따라서 "로그아웃하면 삭제"가 Windows 게스트 계정 기준인지, Edge 게스트 창을 닫을 때 기준인지에 따라 쉬는 시간 안내가 달라진다. Edge 게스트 창이면 창을 닫는 순간 삭제되므로 쉬는 시간에 창을 닫지 않도록 안내해야 한다.
- Edge에는 Google 같은 비Microsoft 계정의 브라우저 로그인을 막는 정책이 있다. 웹사이트(Gemini)에 Google 계정으로 로그인하는 것과는 별개일 수 있으나, 학교 설정에서 실제로 막히는지는 실기기에서 확인해야 한다.
- 조사에서 Gemini 사이트 접속, Padlet, github.io, jsdelivr 같은 개별 사이트 허용 여부를 알려 주는 문서는 찾지 못했다. 학교 웹 필터 정책이 있는지 정보 담당자에게 문의한다.

정보 담당자에게 물어볼 것:
1. (확인됨: Windows 게스트 계정) 절전·잠금 시 세션이 유지되는가? 자동 로그아웃 시간이 있는가?
2. 브라우저는 Edge인가 Chrome인가?
3. gemini.google.com, accounts.google.com, padlet.com, joonssem.github.io, cdn.jsdelivr.net 접속이 허용되어 있는가?
4. 행사 날 노트북 10대 이상을 같은 AP에서 쓰는 데 제한이 있는가?

## 확인된 사항: 게스트는 Windows 게스트 계정 (2026-10-26)
- 로그아웃하면 계정 데이터가 지워진다. Edge 창을 닫는 것만으로는 지워지지 않지만, 로그아웃·종료·재시작·(정책에 따라) 절전은 위험하다.
- 쉬는 시간 안내를 "로그아웃하거나 끄지 말고, 뚜껑을 닫지 않기"로 바꿨다.
- 행사 마지막에 교사가 모든 노트북을 로그아웃해 데이터를 지운다. 반납 전 지워졌는지 확인한다.
- 남은 확인: 절전·화면 잠금 시 게스트 세션이 유지되는지, 비활성 시간 후 자동 로그아웃 정책이 있는지 (실기기 테스트). 브라우저가 Edge인지 Chrome인지, 사이트 접속 허용 여부는 아직 미확인.

## 정보 담당자 문의 결과 (2026-10-27)
- 절전·잠금 (웹검색 + 현장 경험)
  - Intune 공유 기기 설정에는 "절전 전 유휴 시간"(미설정 시 기본 3600초=60분)과 "절전에서 깨어날 때 로그인 요구" 옵션이 있다. 로그인을 요구하면 게스트는 비밀번호가 없어 새 게스트 세션이 될 위험이 있으나, 공개 문서만으로는 게스트 세션이 유지되는지 확정할 수 없다. 학교 테넌트의 실제 값은 관리 센터에서만 확인된다. ([공유 기기 설정 참조](https://learn.microsoft.com/en-us/intune/device-configuration/templates/ref-shared-device-settings-windows), [Set up School PCs 설명](https://technet.microsoft.com/edu/windows/set-up-school-pcs-provisioning-package))
  - 현장 경험: 같은 공용 노트북으로 학생 동아리 활동(방과후, 2차시 분량)을 해 왔고, 사용한 교사들이 문제를 발견하지 못했다. 2차시 분량에서는 문제가 없었다는 근거이며, 3차시와 쉬는 시간 포함 약 2시간은 아직 실측하지 않았다.
- 브라우저: Edge일 가능성이 높다. 게스트 모드에서도 MS Store 앱 설치가 가능하다.
- 사이트 접속: 학교 와이파이에서 대상 사이트 접속을 확인했다 (이전 사전 점검의 접속 항목 해소).
- 동시 접속: 강당에서 학생 아이패드 21대가 동시에 접속되는 것을 확인했다. 노트북 10대 규모는 충분할 것으로 본다.

## 설계 결정
- 정적 사이트(HTML/CSS/JS, 빌드 없음): GitHub Pages만으로 배포, 서버·DB 없음
- 차시·단계·시간·문구는 `config.js`에서만 관리하고, 단계는 순서 번호가 아니라 고정 id로 구분
- 입력은 서버로 보내지 않음. localStorage는 편의용이며 게스트 로그아웃 시 사라지므로 의존하지 않음. 작품은 보호자 Gemini 계정에 남김
- 폰트는 5g 해커톤의 `fonts.css` 그대로(본문 Paperozi, 제목 Ria), 디자인은 Swiss Style(검정·흰색·빨강, 12열 격자)
- 기존 프로젝트(`5g_해커톤`, `1024_family3dpen`)의 소스·DB·배포 설정은 가져오지 않음. 폰트 CSS만 복사

- 교사 공유용 운영안·논의 안건 문서 작성
- 첫 버전 구현: 무대 안내·타이머(스페이스/←→/R/F), 가족용 안내, 2차시 Gemini 프롬프트 만들기, 개인정보 경고
- 5g 폰트 적용, Swiss Style 디자인 적용, 타이머 가로 넘침·가족 화면 겹침 수정

### 2026-10-26 (제출 방식 결정)
- Intune·게스트 로그인 공개 문서 조사 후 위 섹션에 정리
- 3차시 '완성본 내기' 단계에 Padlet 제출 안내와 "Padlet 열기" 버튼 추가 (주소는 `config.js`의 `padletUrl`, 비어 있으면 "선생님이 알려 줘요" 표시)

### 2026-10-27
- 정보 담당자 문의 결과 정리 (절전·접속·동시 접속)
- 저학년 눈높이 문구 정리: `config.js`의 안내·대화 질문을 짧은 문장과 쉬운 낱말로 수정 (보호자→함께 온 어른, 프롬프트→부탁하는 글, 분위기→느낌 등), `guide.js` 라벨 통일. 단계 id·시간은 그대로. 실제 1·2학년 읽기 확인은 아직 안 함.

### 2026-10-27 (방향 반영)
- 목적을 "잘 만들기"에서 "가족이 함께 해결할 일 찾기"로 바꿔 `config.js`·`guide.js` 문구 수정: 2차시 대화 질문, 프롬프트 만들기 항목(해결할 일/누가 불편한지/어떻게 도울지/느낌), 3차시 발표 안내, Padlet 이름 칸에 가족 팀 이름 안내
- 해결할 일 선택지(집안일 나누기 등 4개)는 임시 예시. 교사 논의 후 `promptBuilder.ideas`에서 확정
- 이전에 저장된 입력 형식이 달라져도 오류가 나지 않도록 저장값을 기본값과 합침

### 2026-10-27 (Gemini 입력 주체, 초등학생 이용 법·규정 조사)
- 3차시 '고쳐서 완성하기'는 아이가 고칠 곳을 말하고 함께 온 어른이 Gemini에 입력하도록 안내 (2차시 부탁하는 글은 어른이 복사해 붙여 넣는 방식 그대로)
- 조사 결과 (공개 자료 기준, 법률 자문 아님)
  - Google: 한국에서 자기 Google 계정을 직접 관리할 수 있는 나이는 만 14세 이상. 더 어린 자녀는 부모가 Family Link로 만들고 관리한다. ([Google 계정의 연령 요건](https://support.google.com/accounts/answer/1350409?hl=ko))
  - Gemini 앱: 만 13세(또는 거주국 적정 연령) 미만도 부모가 Family Link에서 사용을 켜면 쓸 수 있다. 한국의 구체 연령은 안내문에 없다. 미성년자용 필터가 적용되지만 완벽하지 않다. ([Gemini 앱 고객센터](https://support.google.com/gemini/answer/16109150?hl=ko))
  - 개인정보 보호법: 만 14세 미만 아동의 개인정보 처리에는 법정대리인 동의가 필요하다. 학교가 구글·MS 계정 로그인으로 AI를 쓰게 하면 동의서 사안으로 보는 해설이 있다 (2차 자료).
  - 교육부·교육청 생성형 AI 활용교육 가이드라인 PDF는 원문 텍스트를 읽지 못했다. 초등학생 이용 연령 기준을 정했는지는 확인하지 못했다.
- 이번 행사 설계에 주는 의미: 학생 본인 계정이 아니라 보호자 계정으로, 보호자가 함께 입력하는 방식이라 위험이 낮다. 학교 계정 로그인이 아니며 학생 개인정보도 입력하지 않는다. 다만 학교 행사이므로 사전 안내문(보호자 동의·참여 안내)과 관할 교육청 지침 확인은 필요하다.
